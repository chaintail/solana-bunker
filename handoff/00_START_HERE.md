## What is locked

- Separate **state PDA** and **treasury PDA**. The treasury receiving address does not depend on the current authorization root or verifier mode.
- Core progression: **SHA-256 secret array → Merkle-committed secrets → XMSS/WOTS+**. XMSS is the centerpiece.
- All three demonstrations manage both native SOL and a new, basic **six-decimal mock-USDC SPL token**.
- Include leaf burning and XMSS-authorized root rotation. Ordinary development-key program upgrade authority is acceptable and must be disclosed.
- Use a fresh developer wallet, local testing, and **devnet by default** for public application deployment. Report the actual cluster before requesting funding. The user approved development-cluster testing; do not revive earlier mainnet ideas.
- No frontend implementation yet. Produce a client/CLI and structured demo evidence for the later UI discussion.
- **SLH-DSA is stretch/future work**, not a prerequisite. Advanced recovery, timelocks, multiple signing devices, and protected upgrade governance are not core deliverables.
