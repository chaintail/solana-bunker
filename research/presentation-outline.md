# UI and presentation narrative

Opening: “You've watched a hundred startup pitches. Unfortunately, this one contains math.”

1. **One receiving address.** Show initialized state and treasury separately; display native/token receiving addresses and evidence level. Anchor the claim in same program/cluster/vault.
2. **The simplest lock.** Show one-time secret array storage and a legitimate transfer. Replay the scripted copied-witness destination substitution; label the intended attacker success.
3. **A smaller commitment.** Show the Merkle proof and measured account allocation. Repeat the bearer attack so storage compression and message authentication remain distinct.
4. **Sign the action.** Show XMSS authorization with amount/destination, epoch, nonce and leaf. Copy unchanged intent once, then attempt an edited destination/amount; display verified rejection stage.
5. **Retire and replace.** Show a bounded burn and old-root-signed rotation to fresh authority. Keep treasury/token receiving addresses visible while root/epoch change; show new-root transfer and old-root rejection.
6. **Show the receipts.** Link raw run IDs, CUs, bytes, account allocation and public transaction confirmations. Keep the ordinary trusted upgrade/demo administration qualification on the same frame as the security conclusion.

Use client structured events as input; never publish seed material, pending bearer secrets or signer journals. Blank/unmeasured fields stay visibly unknown. No frontend or slide deck is included in this sprint.
